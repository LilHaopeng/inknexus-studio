# 小说正文写作

把已有世界观和大纲转化为有具体场景、鲜活人物行动、母语语感与页面呼吸感的小说正文。

> **核心原则（硬正典连续，松表达定调）**：严格锁死世界正典、因果落地、POV 边界与跨章连续性；表达层以本篇 `00_文风与声口卡.md` 的**定调原声切片**为最高基准，不拿单一“克制文学模板”覆盖所有流派。`lint_prose.py` 仅作语感与分布体检镜子，**严禁为清零警告机械切段、凑水对白或硬换生僻同义词**。若需写 5 万字以内强网感脑洞短篇/微短剧爽文，可直接使用更轻快的 `webnovel-short-studio`。

## 语言与起笔约定

- **默认简体中文**：除非用户明确指定其他语言（或提供非中文原稿并要求沿用原语种续写），对话沟通、台账维护与小说正文默认使用**简体中文**，采用中文母语叙事节奏（零形回指、意合推进、留白收束）与中文小说标点规范。
- **多语种主动切换**：用户可随时指定用**英文（English）**、**繁体中文**、**日文**或其他语言起笔。切换语言后，将目标语种写入 `正文/写作状态.md` 与 `正文/00_文风与声口卡.md`，同步切换为该语种的母语叙事技法、对白标点、排版字体及 `lint_prose.py --lang` 检查模式，避免把中文腔硬译成外文或把英文从句腔带入中文。

## 任务路由

按用户实际需求进入对应阶段：`estimate` 篇幅盘点；`audition` 文风设计与试写；`draft` 正文撰写或续写；`revise` 润色修订；`audit` 连续性与语感审校；`deliver` 排版导出。仅执行本次需要的阶段；用户已明确的篇幅、文风、语言和写作授权直接沿用，缺少会实质改变走向的关键信息时先沟通确认。

## 项目体检与正典边界

动笔前先只读识别项目现有的世界观、章纲、人物与状态台账、已写正文及版本号。优先适配 `story-world-architect` 与 `story-outline-architect` 的目录约定，也兼容用户自定义的目录或等价文档；详见 [产物契约](references/artifact-contract.md)。

- **章纲与依据**：依据本章可执行章纲或用户给出的剧情安排行文；缺少关键目标、转折或必要前提时先说明缺口。
- **正典遵循与生活留白**：遵守已确认的世界规则、制度、势力、角色认知边界及锁定剧情。日常饮食、街道器物、市井闲谈等普通生活质感可在不抵触设定的前提下自然生发（优先调用世界观接口中的「语言与日常肌理切片」）；不私自编造会改变规则边界、权力格局或后续因果的核心设定。
- **冲突上报**：发现大纲动作与世界硬规则或前文事实冲突时，列出证据与影响并给出修复选项，经用户确认后执行（必要时登记 `CR-NNN` / `WCR-NNN`）。
- **轻量台账兼容**：角色状态、伏笔、信息差等台账缺失时，从现有材料整理带出处的临时摘要并标明未知项，沿用项目既有格式。

## 字数预估与缩放

需要盘点篇幅或扩缩大纲时，读取 [字数预估与缩放](references/word-count-and-scaling.md)，可运行：

```text
python <skill-dir>/scripts/estimate_word_count.py --root <项目根>
```

按 `--help` 传入已知总章数 `--total-chapters` 或单章目标 `--target-words`，结合章节实际冲突与留白需求评估承载力。需大幅压缩或扩充篇幅时，先调整章节因果与场景颗粒度（取得必要授权后同步章纲），不靠删断主线省字数，也不靠站桩心理或重复景物注水。

## 文风校准与母语语感

设计文风、试写定调或打磨文字质感时，读取 [文风与去 AI 味](references/style-and-anti-ai.md)：

- **声口定调与原声锚点（防千书一面）**：预设八大流派可自由组合。必要时取首章核心场景试写 500–800 字，确认后将参数及 **150–250 字定调原文切片 + 核心角色原声台词** 固化入 `正文/00_文风与声口卡.md`；该原声切片优先级高于任何通用写作技法，防止长篇连载中段声口漂移或滑向单一文学基底腔。
- **自定义流派研究**：用户提出特定作家、作品或复合流派时，优先通过可用的搜索与网页工具核实资料并解构为五维可执行技法；无法联网时使用用户样本或坦诚标注“暂拟未核实”，绝不编造链接与出处。
- **精准去废料与反过度约束**：重点剔除纯翻译腔、工业神态套话与叠加式描写；承前省主语、半句留白、感官配额与手头事务均属**按题材按需选用的技法工具**，不强迫所有流派一律克制留白，**严禁封杀正常高频中文词或一刀切禁标点/比喻**。

## 逐章执行、页面观感与审校

撰写连载章节时读取 [长篇执行](references/long-form-execution.md)，审校与回写时读取 [审校与连续性](references/audit-and-continuity.md)：

1. **按需装配上下文**：加载声口卡（含定调原声切片）、本章细纲/场景、上章交接卡（含上章起收镜头方式）、出场角色状态、相关伏笔与触发的世界规则。严格隔离“作者真相”与“角色当前认知”。
2. **大纲消融与老手视角**：将细纲的 `Goal / Choice / Cost` 自然融进符合本篇题材的场景交锋与动作对话，消除分段打卡感（不强迫快节奏或直球交锋场景硬套慢热“手头事务”）；本世界土著角色对常态规则熟视无睹，只写当下的摩擦与异常，不借角色内心给读者写制度说明书。
3. **页面呼吸感与视觉律动**：按流派与阅读介质自然交替长叙述段、短动作段、无旁白裸对白连击与单句气口，既避免连续等高“豆腐块”，也警惕过度切段造成的均匀“AI 电报排骨体”；杜绝给普通词汇乱打强调引号，错开相邻章节的开篇与收尾句式。
4. **审校与状态回写**：初稿完成后运行 `python <skill-dir>/scripts/lint_prose.py --file <章节文件> --profile <standard|fast|literary>`（可加 `--target-words` 与 `--lang`），将其作为客观体检镜子复核分布信号与明显套话，绝不机械清零；最后依据正文实际发生的事实更新 `追踪/章节交接.md` 及相关状态台账。

## 纯净正文与排版导出

章节 Markdown 仅保留章标题与纯净小说正文，工作台编号、字数统计与自检说明一律留在对话或追踪台账中。初始化目录可运行 `scripts/init_prose_project.py`。

需要导出 `.docx` 阅读稿时，可调用内置排版脚本生成书籍级（`book`）或屏幕轻读级（`screen`）文档：

```text
python <skill-dir>/scripts/build_prose_docx.py --chapters-dir <正文目录> --out <输出.docx> --title <书名> --preset book
```

若环境具备 LibreOffice 与 PDF 渲染依赖，转出 PDF 逐页检查版面、分页与天头地脚后再交付。
